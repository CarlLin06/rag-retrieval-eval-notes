# rag-retrieval-eval-notes

中文 RAG 检索层的多路召回融合与评测方法笔记：把一次独立技术评审里可公开的技术推演，整理成三篇推导 + 一个可跑的最小实验。

全部内容基于自造样例和公开原理，不含任何客户信息、系统架构、真实数据或参数值。

## 核心结论

**中文场景下，关键词检索有一个固定的失效边界，多路召回不是优化项，是结构性必需。**

当用户的口语问法与知识库措辞在字面上错开——哪怕只差一个字，比如「店保」对「店铺保修」——词级倒排（分词后）和 trigram（三字滑窗）会**同时**断裂。断点在「建立候选集」这一步，早于任何排序和打分，所以它不是能靠换分词器或调参补上的质量问题，而是关键词匹配机制本身的定义域边界（推导见 [01](docs/01-中文检索的失效边界.md)）。

补这个洞要靠盲区不同的另外几条路：人工别名（认字面对应，准但覆盖窄）、语义向量（不看字面，能救回同义压缩，但在型号编号上失灵）。四条路盲区互不重叠，没有任何单独一路的盲区能被其余几路同时盖住——这就是「多路」的必要性来源。

而把四条量纲完全不可比的路（BM25 无界、Dice 有界、余弦有界）合成一个排序，不能在原始分数上做加权、卡阈值或归一化，这三种做法分别栽在量纲漂移、权重不可表达、分布依赖上。正确解是 RRF：丢掉原始分数，只用名次，`Σ w/(k+rank)`，k=60 让融合奖励跨路共识而非单路碾压（推导见 [02](docs/02-RRF融合.md)）。

评测层的核心结论独立于检索：判定门槛调优本质是跷跷板，降误拦必然抬硬答，所以验收标准若要求两个对立指标同时改善，在数学上就立不住；正确形态是「风险指标钉死上限、主指标在约束内优化」，且调参集与验收集必须分开、稀有类单独组安全集、小样本用条数、调参前冻结一切（推导见 [03](docs/03-调参类工作的验收方法.md)）。

## 快速开始

```bash
python3 experiments/fts5_lab.py        # 跑完整六个实验
python3 experiments/fts5_lab.py -i     # 交互模式，自己输问法看断在哪
```

只依赖 Python 标准库（`sqlite3` 的 FTS5 扩展），无需安装任何东西。
