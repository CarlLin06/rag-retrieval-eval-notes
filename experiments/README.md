# experiments

一个自包含的最小实验，把前面三篇文档里的推导全部跑成可以看的输出。没有任何外部依赖，只用 Python 标准库里的 `sqlite3`（FTS5 是 SQLite 自带的全文检索扩展）。

## 跑法

```bash
python3 fts5_lab.py        # 跑完整六个实验，全部打印到终端
python3 fts5_lab.py -i     # 跑完之后进交互模式，自己输问法看断在哪
```

要求：Python 3，且 SQLite 编译时开启了 FTS5（macOS 自带的 Python、绝大多数 Linux 发行版都默认带）。验证一行：

```bash
python3 -c "import sqlite3; sqlite3.connect(':memory:').execute(\"CREATE VIRTUAL TABLE t USING fts5(x)\"); print('FTS5 可用')"
```

## 实验室里有什么

三条自造知识（D1/D2/D3）和一个自造的口语问法「你们的两年保修是店保吗」。所有数据都在脚本里写死，纯推演，不含任何真实来源。整个脚本建一个内存库、四条召回路、一次 RRF 融合，跑完即销毁。

## 每个实验演示什么

| 实验 | 演示的事 | 对应文档 |
|---|---|---|
| 一 · 分词 | 一句话被最大正向匹配切成什么，「店保」在分词这一步就和知识库的「店铺」错开 | [01](../docs/01-中文检索的失效边界.md) |
| 二 · 词级 FTS | 分词后的倒排 + BM25，看它靠「两年/保修」捞回 D1，但完全没碰到「店保」这个区分点 | [01](../docs/01-中文检索的失效边界.md) |
| 三 · trigram | 三字滑窗，看「是店保/店保吗」怎么和「是店铺/店铺保」逐窗错位，差一个字全断 | [01](../docs/01-中文检索的失效边界.md) |
| 四 · 别名 | 二元组 Dice 系数，看人工手写别名怎么把「店保」救回来，以及没人写就是 0 的代价 | [01](../docs/01-中文检索的失效边界.md) |
| 五 · 语义 | 用演示用的相似度值，说明语义路为什么是唯一不看字面、能救回「店保」的路，以及它在型号上的短板 | [01](../docs/01-中文检索的失效边界.md) |
| 六 · RRF 融合 | 把四条路的名次用 `w/(k+rank)` 合成最终排序，看 k=60 怎么奖励跨路共识、原始分数怎么全程不参与 | [02](../docs/02-RRF融合.md) |

## 几个可以自己动手的点

- **改 `WEIGHTS` 和 `K`**（脚本里实验六上方）：把 `K` 从 60 调到 0，重跑，看 D1 和 D2 的分差怎么被拉大——这就是「单路头名主导」效果的回归，对应文档 02 里 k 的作用那一节。
- **交互模式输自己的问法**：`python3 fts5_lab.py -i`，输入任意口语问句，脚本会实时打出它在词级、trigram、别名三条路各自的命中情况。专门试那些和知识库措辞差一两个字的问法，直观看关键词路在哪断、哪条路兜住了。
- **给别名表加一条**：在 `ALIASES` 里给某条文档补一个新说法，重跑，看别名路的命中和最终排序怎么变——这是运营侧「手写别名」在系统里真实的杠杆。

## 关于语义路的说明

实验五的余弦相似度是写死的演示值，不调真实 embedding 服务。原因是想让整个实验零依赖、一条命令跑通，同时又能把语义路的**行为特征**（不看字面、能救回同义压缩、但在型号编号上会失灵）讲清楚。真实环境里这一路换成对接 embedding 模型即可，融合逻辑（实验六）不用动——RRF 只吃名次，不关心名次是哪条路、用什么模型排出来的。
