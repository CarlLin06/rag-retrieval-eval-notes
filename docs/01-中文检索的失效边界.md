# 中文检索的失效边界

关键词检索在中文里有一个固定的失效模式，它不随分词器的好坏、也不随索引方式的选择而消失。本篇用一个自造样例把这个边界的位置精确定位到「哪一步、因为什么断掉」，并给出可复现的验证。

结论先放这里：当用户的问法与知识库的措辞在字面上错开——哪怕只错一个字——词级倒排和 trigram 会**同时**失效，而且失效点在检索发生之前，属于机制本身的盲区，不是检索质量问题。所有实验可在 `experiments/fts5_lab.py` 里一次跑通。

## 样例

知识库里有一条（记为 D1）：

```
标题：两年保修是店铺保修还是官方保修
正文：本店销售的机器提供两年保修，由店铺承担，非厂商官方保修。
```

用户这样问：

```
你们的两年保修是店保吗
```

语义上这是同一件事：用户想确认这两年保修是店家自己兜的还是厂商官方的。人一眼能对上。下面看两条关键词路怎么处理它。

## 路 A：词级 FTS（分词后倒排）

词级检索的第一步是分词，它决定了后面倒排表能命中什么。用最大正向匹配把两句切开：

```python
VOCAB = ["两年", "保修", "店铺", "官方", "机器", "厂商", "你们", "店保"]

def tokenize(text, vocab=VOCAB):
    out, i = [], 0
    while i < len(text):
        for size in range(4, 0, -1):          # 先试长词，再试短词
            piece = text[i:i + size]
            if piece in vocab:
                out.append(piece); i += size; break
        else:
            i += 1                            # 一个词都没匹配上，跳过这个字
    return out

print(tokenize("你们的两年保修是店保吗"))
# ['你们', '两年', '保修', '店保']
print(tokenize("两年保修是店铺保修还是官方保修"))
# ['两年', '保修', '店铺', '保修', '官方']
```

对齐两边的词集合：

```
用户切出：你们 / 两年 / 保修 / 店保
D1  切出：两年 / 保修 / 店铺 / 官方
对上：两年、保修
对不上：你们、店保
```

关键的那个词——「店保」——切出来了，但它在 D1 里不存在。D1 写的是「店铺」。倒排表是一个「词 → 文档」的精确映射，「店保」这个键在表里根本没有条目，查它返回空。词级路对这个词无能为力，不是因为它排序排错了，而是因为它压根没有可查的入口。

它靠剩下的「两年」「保修」还是把 D1 捞了回来（BM25 会让命中词更多、文档更短的 D1 排在前面），但请注意：**它捞回 D1 靠的是那些不关键的词**。用户真正想问的区别点「店保 vs 官方保修」，词级路完全没参与判断。换一个正文里连「保修」都不出现、只出现「店保」语义的文档，词级路就会彻底交白卷。

## 路 B：trigram（三字滑窗）

trigram 不分词，它把文本切成所有连续三字片段，用片段做倒排。它的设计初衷正是绕开分词——既然分词会在「店铺/店保」这种地方切错，那就不分词，直接按字符滑窗匹配。看它能不能救回来：

```python
def trigrams(text):
    return [text[i:i+3] for i in range(len(text) - 2)]

q = trigrams("你们的两年保修是店保吗")
d = trigrams("两年保修是店铺保修还是官方保修")

print([t for t in q if t in d])      # 重合
# ['两年保', '年保修', '保修是', '修是店']
print([t for t in q if t not in d])  # 断裂
# ['你们的', '们的两', '的两年', '是店保', '店保吗']
```

看断裂的那两片：`是店保`、`店保吗`。D1 对应位置是 `是店铺`、`店铺保`。用户说「店保」，知识库写「店铺」，差的这一个字「铺」，让**包含它的每一个三字窗口全部错位**。一个字的差异，在 trigram 里不是影响一个片段，而是影响以它为中心的连续三个窗口。

trigram 同样靠前半句重合的 `两年保` `年保修` 把 D1 排到了第一，但和词级路是同一个病：真正区分语义的后半句「是不是店保」这一段，两条路一起断在了同一个字上。

## 为什么差一个字就全断

把两条路的失效点并排放：

| 路 | 匹配单位 | 「店保」在这里发生了什么 |
|---|---|---|
| 词级 FTS | 分词后的词 | 「店保」是一个倒排表里不存在的键，查询返回空 |
| trigram | 连续三字片段 | 含「店保」的三个窗口全部与「店铺」错位，无一命中 |

两条路的匹配单位不同（词 vs 三字窗），但它们共享同一个前提：**匹配建立在字面片段的重合上**。用户的「店保」和知识库的「店铺保修」在字面上没有足够长的公共子串——「店保」这两个字在 D1 里从不相邻出现（D1 里「店」后面永远跟「铺」）——于是无论你按词切还是按窗切，都找不到落点。

这就是失效边界的准确位置：它不在排序阶段，不在打分阶段，而在**建立候选集**这一步。排序算法再好，也只能对已经进入候选集的文档排序；一个从未进入候选集的文档，BM25 给不了它分数，因为它根本没在结果里。

再强调一遍这个容易被误判的点：这里没有发生「检索质量下降」。词级和 trigram 都正常工作、都返回了它们该返回的东西。是「店保」这种**同义压缩的口语问法**天生落在关键词匹配的定义域之外。你可以把分词器换成 jieba、换成更大的词典、加更多用户词，只要词典里没有恰好把「店保」映射到「店铺保修」的规则，结果不变。这不是调参能补的洞，是机制的边界。

## 那靠什么救

能救回「店保」的，是不依赖字面重合的路：

- **人工别名**：运营手写一条「保修是店保吗 → D1」。它不猜，只认写过的对应关系，所以准，但覆盖不到没人写过的说法。用二元组 Dice 系数量一下，用户问句和别名「保修是店保吗」的字面相似度能到 0.667，足够进候选。代价明确：没人写「店保」，这一路就是 0。
- **语义向量**：把两句都编码成向量，算余弦相似度。它完全不看有没有共同的字，只看意思，所以是四条路里唯一一条在「没有别名、字面又错开」时还能把 D1 捞回来的。它对 D1 的相似度能到 0.87。它的短板在另一个方向——型号、编号这种「意思几乎一样但必须区分」的场景，比如 XK-2000 和 XK-3000 在它眼里近乎同义，这时候反而要靠字面精确的关键词路来兜。

四条路的盲区互不重叠，这正是多路召回不是「锦上添花」而是「结构性必需」的原因：没有任何单独一路的盲区，能被其余几路同时盖住。「店保」这个样例里，词级和 trigram 一起失效，别名因为恰好有人写过而命中，语义因为不看字面而命中——**同一个 query，靠的是不同机制的两条路，缺一条它就可能掉出候选集**。

怎么把这几条量纲完全不同的路合成一个最终排序，是下一篇 [02-RRF融合](02-RRF融合.md) 的事。多路召回自身的必要性，到这里已经由「一个字的断裂」证明完毕。
