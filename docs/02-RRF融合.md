# RRF 融合

[上一篇](01-中文检索的失效边界.md)证明了单路关键词检索会在中文口语问法上成片失效，多路召回是结构性必需。这一篇解决随之而来的工程问题：四条路——词级 BM25、trigram BM25、别名 Dice、语义余弦——各自吐出一个分数，量纲完全不同，怎么合成一个可信的最终排序。

结论先放这里：不要在原始分数上做任何算术。先把每条路的原始分数丢掉，只保留它给出的名次，再用 RRF（Reciprocal Rank Fusion，排名倒数融合）把名次合起来。下面先证明三种「在分数上动手」的直觉方案为什么都会塌，再给出 RRF 并用样例走一遍。

## 三种在分数上动手的方案，为什么都不行

### 方案一：加权求和

最直觉的做法：`final = a·BM25 + b·Dice + c·cosine`。它错在量纲不可比。

- BM25 的取值范围是 `[0, +∞)`，无上界，且它的绝对大小依赖语料统计量（IDF 里的文档频率、平均文档长度）。同一个查询，语料从一万条涨到十万条，IDF 变了，BM25 的绝对值整体漂移。
- Dice 系数是 `[0, 1]`，有界。
- 余弦相似度是 `[-1, 1]`（非负归一化向量下是 `[0, 1]`），有界。

把一个能到 2.7 的 BM25 和一个最多到 0.61 的 Dice 相加，BM25 在数值上天然压倒 Dice，但这个压倒关系毫无意义——它们度量的是完全不同的东西，一个是词频-逆文档频率的加权，一个是字符二元组的重合比例。你调 `a` `b` `c` 想找平衡，但因为 BM25 的绝对尺度会随语料漂移，今天调好的权重，明天语料一变就失衡。你不是在调权重，是在追一个移动的靶。

### 方案二：每条路各设阈值

那不加了，改成每条路自己卡门槛：`BM25 > 2.0 且 Dice > 0.3 且 cosine > 0.7`，过了的取并集。它错在阈值是闸门，不是权重，表达不了「这条路比那条路重要」。

你想说「别名路的一次命中，比词级路更值得信」，用阈值没法表达这个 1.3 倍的相对权重——阈值只能回答「过没过」，回答不了「值多少」。更糟的是漏掉边缘文档：一个文档在每条路上都差一点点过线、但综合起来明明很强，在「与」逻辑下一分不得；换成「或」逻辑，又会把每条路的噪声全放进来。阈值这个工具的表达力，装不下「加权融合」这件事。

### 方案三：归一化到同一量纲再统一卡

再退一步：先把每条路的分数归一化（min-max 或 z-score）到 `[0,1]`，这样量纲统一了，再加权或卡阈值。它错在归一化依赖当前这批结果的分数分布，分布一变，一切重调。

min-max 归一化是 `(x - min) / (max - min)`，它把当前召回批次里的最高分锚成 1、最低分锚成 0。问题是这个 min 和 max 是**这一次查询**的结果决定的：

- 这次查询恰好召回一个 BM25 高达 27 的文档，其余文档除以这个 max，归一化分数全被压扁到接近 0。
- 下次查询最高的 BM25 只有 3，同样一个真实质量的文档，归一化后可能是 0.8。

同一个文档、同样的真实相关性，归一化分数在两次查询间天差地别，因为分母变了。你在今天的分布上卡好的阈值，换一批查询就失准，于是你陷入无休止的重调。z-score 同理，它依赖这批结果的均值和标准差，一个离群文档就能把整个分布拉歪。

## RRF：只用名次

三种方案的共同病根，是它们都试图**保留并比较原始分数**。RRF 的做法是把原始分数彻底扔掉，只留名次。

对文档 d，它在第 i 条路里排第 `rank_i(d)` 名（名次从 1 开始），融合分数是：

```
RRF(d) = Σ_i  w_i / (k + rank_i(d))
```

- `rank_i(d)`：文档 d 在第 i 条路的名次。没进这条路的候选集，这一项记 0（不贡献）。
- `k`：一个平滑常数，经典取 60。
- `w_i`：第 i 条路的权重。基础 RRF 里 `w_i = 1`；带权重版把它拿出来单独设。

为什么这样就绕开了前面三个坑：名次是**无量纲**的，也**不依赖分布**。BM25 是 2.7 还是 27，排第一就是第一；余弦是 0.87 还是 0.9，排第一也还是第一。名次这个量，天生对「绝对尺度」和「分布形状」免疫，而那正是前三种方案翻车的地方。RRF 不是把量纲问题解决得更好，是直接不进入那个问题。

### k=60 在做什么

`k` 控制「排在前面」这件事的边际收益衰减得有多快。看相邻两名的分差随 k 怎么变：

```python
for k in (0, 5, 60):
    r1 = 1 / (k + 1)
    r2 = 1 / (k + 2)
    print(f"k={k:>2}  第1名={r1:.4f}  第2名={r2:.4f}  第2名/第1名={r2/r1:.3f}")
# k= 0  第1名=1.0000  第2名=0.5000  第2名/第1名=0.500
# k= 5  第1名=0.1667  第2名=0.1429  第2名/第1名=0.857
# k=60  第1名=0.0164  第2名=0.0161  第2名/第1名=0.984
```

`k=0` 时，第一名的价值是第二名的两倍——某一路的头名会以碾压性优势主导融合结果，只要它在一条路排第一，其余路怎么投票都很难翻盘。`k=60` 时，第二名拿到第一名 98.4% 的分，相邻名次几乎等价。

这个「压平」正是要的效果：**当相邻名次几乎等价，一条路的头名就不再能单独定胜负，文档必须在多条路上都排得靠前，才能在总分上赢**。RRF 于是奖励「跨路共识」，而不是「单路碾压」。k 越大压得越平、越看重共识；k 越小越尖、越容易被单路头名主导。60 是经典默认值，来自 Cormack 等人 2009 年提出 RRF 的原始论文，工程上是一个稳的起点，真要动，方向是「更看重共识就调大，更信任某条强路的头名就调小」，而不是随手试。

### 带权重版

基础 RRF 平等对待每条路，但四条路的可信度并不相等。人工别名是运营一条条手写的高精度对应，一次命中几乎不会错，理应最重；语义次之；两条关键词路作为基线，权重 1.0。于是给出：

```python
WEIGHTS = {"词级": 1.00, "trigram": 1.00, "别名": 1.30, "语义": 1.15}
```

权重乘在名次贡献上：`w_i / (k + rank_i)`。注意它和「加权求和」的本质区别——这里 `w_i` 乘的是**无量纲的名次倒数**，不是带量纲的原始分数。别名权重从 1.0 提到 1.3，含义是「别名路的一次靠前命中，值 1.3 个基线路的同名次命中」，这是一个干净、可解释、不随语料漂移的相对信任度；而在加权求和里同样提 1.3 倍，含义会被 BM25 的绝对尺度污染，完全不是一回事。

## 用样例走一遍

沿用[上一篇](01-中文检索的失效边界.md)的样例：用户问「你们的两年保修是店保吗」，知识库三条文档 D1/D2/D3。四条路各自跑完，给出的名次是（`—` 表示没进这条路的候选集）：

| 文档 | 词级 | trigram | 别名 | 语义 |
|---|---|---|---|---|
| D1 | 第1 | 第1 | 第1 | 第1 |
| D2 | 第2 | — | — | 第2 |
| D3 | — | — | — | 第3 |

回顾一下这些名次的来历：词级路靠「两年」「保修」把 D1、D2 都捞出、D1 更相关排第一；trigram 只有 D1 有重合的三字窗，别名只有 D1 有人手写过，这两路 D2/D3 直接缺席；语义路三条都给了相似度，按 0.87 / 0.41 / 0.12 排成 1/2/3。关键的观察是：**两条关键词路在 D1 上都失效于「店保」那个字，但它们没把 D1 排除，只是让 D1 靠前半句的字面重合勉强上榜**；真正把 D1 钉在第一的信心，来自别名和语义。

取 `k=60`，逐条算：

```
D1 = 词级 1.00/(60+1) + trigram 1.00/(60+1) + 别名 1.30/(60+1) + 语义 1.15/(60+1)
   = (1.00 + 1.00 + 1.30 + 1.15) / 61
   = 4.45 / 61
   = 0.0730

D2 = 词级 1.00/(60+2) + 语义 1.15/(60+2)         （trigram、别名缺席，记 0）
   = 2.15 / 62
   = 0.0347

D3 = 语义 1.15/(60+3)                             （其余三路缺席）
   = 1.15 / 63
   = 0.0183
```

最终排序：

```
第1名  D1  0.0730   两年保修是店铺保修还是官方保修
第2名  D2  0.0347   电池健康度低于80%可以更换
第3名  D3  0.0183   退货地址在深圳龙华
```

D1 之所以以两倍于 D2 的分数胜出，不是因为它在某一路碾压，而是因为它是唯一一个**四条路都把它排进前列**的文档——这正是 k=60 想奖励的跨路共识。而从头到尾，BM25 的 2.336、Dice 的 0.667、余弦的 0.87 没有一个进入过这个计算，它们只用来在各自路内排出名次，排完即弃。这就是 RRF 绕开量纲的方式：它把「怎么比较不可比的分数」这个问题，换成了「怎么合并可比的名次」。
