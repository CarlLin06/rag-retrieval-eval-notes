# 调参类工作的验收方法

前两篇讲检索机制。这一篇换一个层面：当你把召回和判定门槛调完，怎么验收才算数。这是一套方法论，比具体的检索技巧更值得写清楚，因为调参类工作的验收错误，几乎都不是错在「调得不够好」，而是错在「验收标准本身在数学上就立不住」。下面每一条都给出为什么，不是清单式的规定。

贯穿全篇的对象是**判定层门槛**：系统在召回之后、回答之前，用一个分数阈值决定「这个问题有没有把握答」——过线就答（硬答），不过线就兜底（转人工、反问、或明确说不知道）。调这个门槛，是最典型也最容易验收翻车的调参工作。

## 一、门槛调优的本质是跷跷板

先把这件事的数学结构摆出来，后面所有结论都从这里长出来。

设每个问题有一个把握分 `s`（越高越有把握答对），门槛 `t`，规则是 `s ≥ t` 就答、否则兜底。系统会犯两类错：

- **硬答**（该兜底的却答了）：本该转人工的问题，分数偏偏过了线，系统给了个不靠谱的答案。`硬答 = P(s ≥ t | 本该兜底)`。
- **误拦**（该答的却兜底了）：本来能答好的问题，分数没过线，被拦下来白白转了人工。`误拦 = P(s < t | 本该答)`。

现在只动 `t` 这一个旋钮，看两类错怎么走：

```
t 调低  →  更多问题过线  →  硬答 ↑，误拦 ↓
t 调高  →  更少问题过线  →  硬答 ↓，误拦 ↑
```

两类错被同一个 `t` 反向绑定。压低一头，另一头必然抬起来。这就是跷跷板：**单个门槛，两类误差，天生对立**。这不是工程没做好，是单阈值决策的数学定义决定的——它就是 ROC 曲线上的一个工作点，你沿着曲线滑动 `t`，只是在曲线上换位置，不可能同时让两个坐标都变小。

一句话记住区别：**调门槛是在一条固定的曲线上移动工作点；只有改模型、改特征、改召回，才是把整条曲线往外推**。后者能同时改善两类错，前者不能。验收一个「门槛调优」任务，必须建立在「你在移动工作点，不是在推曲线」这个前提上。

## 二、所以验收不能要求两个指标同时改善

直接推论：如果验收标准写成「相比基线，硬答率要下降，且误拦率也要下降」，这在门槛调优的范围内是数学上做不到的。你在要求跷跷板两头同时落地。

这个错误在实践里极其常见，因为它听起来无比合理——「我们既要更安全又要更好用」——但它把一个「选工作点」的任务，误当成了「推曲线」的任务下了指标。结果只有两种：要么调参的人交不出活（因为真的做不到），要么他用别的手段把数字凑出来（最常见的是在验收集上过拟合，见第四节），埋一个上线就炸的雷。

正确的做法在下一节。这里先立一个判断力：**看到「两个对立指标都要改善」的验收标准，第一反应应该是「这是不是一个纯门槛调优任务」**。如果是，这个标准本身就该打回去重写，而不是硬着头皮去调。

## 三、正确的写法：约束下优化

跷跷板不能两头同时压，但你可以**把一头钉死在可接受的高度，然后尽力压另一头**。这就是约束优化，也是这类任务唯一在数学上成立的验收形态：

> 以风险指标不超过上限为约束，在此约束下优化主指标。

落到门槛调优：

- **风险指标（约束）**：硬答率。它对应真实伤害——答错、误导、合规问题。给它一个硬上限，比如「硬答率 ≤ 2%」。这是不可谈判的红线。
- **主指标（优化目标）**：误拦率（或等价的召回率、自动化率）。在硬答率不破 2% 的前提下，把误拦压到最低。

写成一句可验收的话：**「在硬答率 ≤ 2% 的约束下，误拦率相比基线下降」**。这句话可验收，因为它尊重了跷跷板——它没有要求硬答也下降，只要求它不越线。这在数学上完全可以达到，你只是在 ROC 曲线上，往「约束边界」那个点滑过去。

这套框架就是 Neyman–Pearson：固定一类错误的上限，最小化另一类错误。它之所以是对的，恰恰因为它承认了两类错不能同时优化，转而问一个能回答的问题——「在我能容忍的风险内，好用性最好能到哪」。

哪个当约束、哪个当目标，由业务后果的不对称性决定：一次硬答（把用户导向错误答案）的代价，通常远高于一次误拦（多转一次人工）。代价高的那类当约束、钉死；代价低的那类当目标、去优化。

## 四、调参集与验收集必须分开

门槛 `t` 是在一批带标注的样本上挑出来的——你试不同的 `t`，看哪个在这批样本上硬答/误拦的平衡最好。这里藏着一个陷阱：**如果挑 `t` 和验收 `t` 用的是同一批样本，你挑出的 `t` 会贴着这批样本的具体分布长，验收自然好看，上线立刻现形。**

道理和机器学习的训练/测试划分一模一样，只是这里被调的「参数」是那一个门槛 `t`。你在一批样本上遍历 `t`、选出表现最好的那个，本质是在用这批样本的噪声帮你做选择——某个 `t` 恰好卡在两个样本分数中间、让这批数据的指标特别漂亮，但那个位置是这批样本的偶然，不是真实分布的性质。换一批线上流量，这个精心卡出来的位置就散了。

所以：

- **调参集**：用来遍历 `t`、挑门槛。可以反复看、反复试。
- **验收集**：挑门槛的过程从头到尾不许碰它。门槛定死之后，只在它上面跑一次，出的数字才是验收结论。

一旦你为了「让验收集数字更好」回头去改门槛，验收集就退化成了第二个调参集，你又回到了过拟合。验收集的价值，全部来自它的「没被看过」。看一次，用一次，就够了。

## 五、稀有类样本单独组成安全集

有些类别的样本天生稀少——某种罕见但高危的问法、某类必须绝对答对的合规问题——整个数据集里可能就三五条。这种样本不能混进常规分层指标里，否则**一条样本就能决定整个验收结论**。

数学上看就明白：某个高危类只有 4 条样本，它在常规指标里要么以「4 条的命中率」参与（一条错就是 25% 的波动），要么被整体平均稀释到看不见。前者让你的验收指标被一条样本的偶然绑架，后者让这个本该最受重视的类别在总指标里几乎没有存在感——两种都错。

正确做法是把它们抽出来，单独组成一个**安全集**，用硬门槛而不是平均指标来验收：

> 安全集上，高危类零灾难性失败（不是「准确率 95%」，是「0 次」）。

安全集不参与常规分层统计，它是一道独立的闸门：过不了，整个验收不通过，无论主指标多漂亮。这样一条稀有样本不再能左右主指标的小数点，但它该有的一票否决权，一分不少。

## 六、小样本下用条数，不用百分比

紧接上一条：当某个切片只有个位数样本，指标必须用**条数**报，不能用百分比。

`85.7%` 这个数字，在 n=7 时是彻头彻尾的虚假精度——它的真身是 `6/7`，翻一条就是 `5/7 = 71.4%`，一条样本晃动 14 个百分点。把它写成 85.7%，是在用小数点后一位的精度，去描述一个一条数据就能抖掉十几个点的量。读的人会被这个精度骗，以为它稳。

所以小样本一律写 `6/7`、`1 失败 / 7 total`，让分母裸露在外。分母摆在那儿，读的人立刻知道这个结论有多脆、经不经得起一条样本的翻转。百分比适合大样本——n 上千时 85.7% 是可信的；n 是个位数时，百分比只制造精度幻觉。

## 七、调参前冻结一切

最后一条是前提，但排在最后是因为它统摄全篇：**开始调参之前，把样本、知识库、配置、模型、代码基线全部冻结。**

调参是一个单变量实验——你动门槛 `t`，看指标变化，把变化归因于 `t`。这个归因只有在「其余一切不动」时才成立。如果调参期间：

- 知识库被人加了几条文档 → 召回变了，指标变化里混进了知识库的贡献；
- 模型或 embedding 版本悄悄升了 → 分数分布整体平移，你之前挑的 `t` 意义都变了；
- 有人顺手改了段召回代码 → 你根本不知道指标是门槛带来的还是代码带来的。

任何一个没冻的变量，都会污染归因，让你无法回答「这个指标改善，是不是我调的门槛带来的」。而回答不了这个，整个调参和验收就失去意义——你交上去的数字，说不清是谁的功劳，也就说不清换个环境还成不成立。

冻结清单，一个都不能少：

- **样本集**：调参集和验收集都定版，中途不增删。
- **知识库**：文档、别名、切分方式全部定版。
- **配置**：除了正在调的那个门槛，其余参数（k、各路权重、召回条数）全部定死。
- **模型**：LLM、embedding、rerank 的版本号锁定。
- **代码基线**：召回、融合、判定的代码 commit 锁定。

冻结之后，你的实验里只剩一个自由变量——那个门槛。这时候指标的每一点变化，才能干净地归因到它身上。验收结论要能复现、能追责、换环境还站得住，全都建立在这一次冻结上。

## 一页纸总结

| 原则 | 为什么 |
|---|---|
| 门槛调优是跷跷板 | 单阈值两类误差反向绑定，是 ROC 工作点的数学性质 |
| 不要求两指标同时改善 | 那是在要求跷跷板两头同时落地，门槛调优做不到 |
| 约束下优化 | 风险指标钉死上限，主指标在约束内优化（Neyman–Pearson） |
| 调参集/验收集分开 | 同集挑门槛=在噪声上过拟合，上线现形 |
| 稀有类单独组安全集 | 否则一条样本绑架主指标；给它独立的一票否决 |
| 小样本用条数 | n 个位数时百分比是虚假精度，分母要裸露 |
| 调参前冻结一切 | 单变量实验才能把指标变化干净归因到门槛 |
